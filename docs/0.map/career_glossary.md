# 職涯 / 生活 / 學習 名詞表

這一類的「名詞」多半是**概念與判準**而不是縮寫——用來在真實情境裡指認「我現在遇到的是哪一種問題」。
文章清單見 [職涯 / 生活 / 學習 索引](career_index.md)。

---

## 一、組織與問責

| 名詞 | 說明 | 出處 |
|---|---|---|
| **眾手問題（problem of many hands）** | 一件事經過很多人的手，結果沒有人為它負責。這是「找 owner」之所以理性的起點——不是管理層愛找戰犯 | [為什麼大公司永遠在找 Owner？](../why-big-companies-hunt-for-owners.md) |
| **「一個名字，不能再多」** | 業界對眾手問題的標準解法：每件事指定唯一 owner。有效，但有極限——**有些系統天生眾手，而 owner 會換人** | [為什麼大公司永遠在找 Owner？](../why-big-companies-hunt-for-owners.md) |
| **問責黑洞** | 找 owner 的陰暗面：當「誰 own」變成追責而非釐清，人會開始躲。結果是願意接的人越來越少，問題越來越沒人碰 | [為什麼大公司永遠在找 Owner？](../why-big-companies-hunt-for-owners.md) |
| **邊界角色** | 夾在兩個組織之間的人（系統整合、平台、SRE 這類）：責任落在邊界上，但邊界不屬於任何一邊的 KPI | [為什麼大公司永遠在找 Owner？](../why-big-companies-hunt-for-owners.md) |
| **N+1 冗餘的組織版** | 基礎設施的常識套到人身上會出事：把人設計成互為備援，等於把「你的工作」拆掉 | [當組織把你設計成備援](../redundancy-overload.md) |
| **兩個 owner = 沒有 owner** | 權責模糊的判準句。備援設計最常見的副作用 | [當組織把你設計成備援](../redundancy-overload.md) |
| **進展感的消失** | 過載真正的傷害不是「累」，而是**再也看不到自己推進了什麼**——所有時間都被切碎在支援別人 | [當組織把你設計成備援](../redundancy-overload.md) |
| **分工不均砸在可靠者頭上** | 過載不是隨機分佈的：工作會流向最不會搞砸的人。這是結構問題，不是個人選擇問題 | [當組織把你設計成備援](../redundancy-overload.md) |
| **RCA / postmortem** | root cause analysis 與事後查驗，是把「究責」轉成「改結構」的工具 | [當責](../當責.md) |

## 二、面試與職涯

| 名詞 | 說明 | 出處 |
|---|---|---|
| **決策外包** | 刷題面試的機制解釋：用一套規則取代面試官的判斷，於是沒有人需要為「看錯人」負責 | [刷題面試](../job_interview.md) |
| **代理指標選錯** | 文章的核心論點——問題不在「用題目篩人」，而在**選的那個代理指標和工作內容脫鉤** | [刷題面試](../job_interview.md) |
| **照抄大廠** | 小公司沿用大廠面試流程卻沒有大廠的招募量與容錯，是最純粹的偷懶 | [刷題面試](../job_interview.md) |
| **T 型人才** | 深度讓你更快解決複雜問題、預見風險、帶人；廣度讓你從全局設計方案、看懂元件之間怎麼互相影響 | [職涯](../career.md) |
| **沒有正式權力的影響力** | 靠建立信任、理解利害關係人的動機、以身作則來帶動——邊界角色最需要的能力 | [職涯](../career.md) |
| **向上管理（managing up）** | 主動與主管溝通，並理解主管的目標與關注重點 | [職涯](../career.md) |

## 三、學習方法

| 名詞 | 說明 | 出處 |
|---|---|---|
| **先 roadmap 再細節** | 進入新領域的順序：先抓高層次概覽與 **pattern**，不要一開始就鑽細節 | [學習](../learning.md) |
| **理解 → 分解 → 再構築 → 整理** | 學習的四個步驟；「學習的本質是放射狀」而不是線性 | [學習](../learning.md) |
| **痛苦 >（快樂＋意義）→ 拖延** | 拖延的判準式：與其罵自己沒紀律，不如去調整等號兩邊 | [學習](../learning.md) |
| **心智圖七步** | 列關鍵字 → 組塊化分類 → 建立關聯 → 架構 → 細節 → 評估 → 視覺化 | [學習](../learning.md) |
| **可理解輸入（comprehensible input）** | 語言學習的主軸：大量、持續、略高於現有程度的輸入，勝過背單字表 | [英文學習](../英文/英文學習.md) |
| **shadowing / 間隔重複** | 輸出端的兩個具體手法：跟讀，以及用 Anki 之類的 spaced repetition 把單字放回情境裡記 | [英文學習](../英文/英文學習.md) |

## 四、工作方式與自我照顧

| 名詞 | 說明 | 出處 |
|---|---|---|
| **拒絕前先問問題** | 說不的具體做法：問要投入多少時間、和三大優先事項的關係——把拒絕變成釐清 | [說不](../說不.md) |
| **As-is / To-be** | 簡報與提案的基本框架：先講現況，再講目標狀態，中間才是你的方案 | [簡報](../簡報.md) |
| **皮質醇** | 心情不好或慢性壓力時大量分泌的壓力荷爾蒙——身體狀態是工作狀態的一部分 | [health](../health.md) |
| **棉花糖實驗的歸因是錯的** | 提醒自己：看到漂亮的結論先問因果是否成立，別把相關當因果 | [反直覺](../反直覺.md) |
